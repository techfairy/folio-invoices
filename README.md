# Folio — personal paid invoices

Небольшое приложение на английском для инвойсов после оплаты работы. Клиенты, история, USD/EUR, гибкая нумерация, налог, предпросмотр и скачивание PDF. Работает на компьютере и телефоне.

## Попробовать локально

Нужен Node.js 24 или новее. В терминале **в папке этого приложения**:

```powershell
npm.cmd ci
npm.cmd run dev
```

Откройте адрес, который выведет Vite (обычно http://127.0.0.1:4177). Если Supabase ещё не настроен, сверху видна полоса **Local mode**. В этом режиме записи сохраняются только в текущем браузере. Сначала заполните **Settings → Your business details**, затем добавьте клиента и создайте инвойс. Не очищайте данные браузера без резервной копии.

## Подключить вход и общую историю

1. Создайте **отдельный проект** на [Supabase](https://supabase.com/dashboard). Приложение не требует платного сервера.
2. В проекте откройте **SQL Editor → New query**. Вставьте всё содержимое `supabase/schema.sql` и нажмите **Run**. Таблица и функция сохраняют данные отдельно для каждого аккаунта; включена Row Level Security.
3. Скопируйте **Project URL** и **Publishable key** из настроек проекта. Используйте ключ вида `sb_publishable_…` либо старый `anon`. **Не используйте secret или service_role.** Эти значения встраиваются в публичную сборку; доступ к данным обеспечивает вход и RLS.
4. Для локального запуска скопируйте `.env.example` в `.env.local`, заполните оба значения и перезапустите Vite.
5. В Supabase **Authentication → URL Configuration** задайте **Site URL**: `https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/`. В список **Redirect URLs** добавьте этот же адрес со слэшем в конце и `http://127.0.0.1:4177/` для локальной проверки. Если Vite выбрал другой порт, добавьте его точный адрес.
6. В **Authentication → Providers** проверьте, что включён Email provider. Приложение поддерживает регистрацию, подтверждение email, вход по email/паролю и сброс пароля. Для восстановления доступа переходите по ссылке из письма в том же браузере, где запрашивали сброс. Для регулярной отправки писем настройте свой SMTP в Supabase.
7. Создайте свой аккаунт через **Create account**, подтвердите email и войдите. Для личного приложения после создания аккаунта можно отключить новые регистрации в Supabase. При этом ваш вход и сброс пароля продолжают работать.

Локальные записи **не переносятся автоматически** в облачный аккаунт. До подключения экспортируйте **Settings → Export backup**, затем войдите и импортируйте файл. Перед заменой приложение показывает состав копии и просит подтвердить замену.

## Выложить на GitHub и открыть онлайн

Загрузите **содержимое папки `invoice-app` в корень отдельного репозитория**. Не загружайте родительское приложение бюджета.

При загрузке через браузер: создайте репозиторий → **Add file → Upload files**, выберите содержимое этой папки. Нужны `src`, `public` (включая `fonts` и лицензию), `supabase`, `tests`, конфигурации и `package-lock.json`. Каталог `.github` содержит скрытый workflow; если он не попал в загрузку, создайте файл через **Add file → Create new file**, укажите имя `.github/workflows/deploy.yml` и вставьте содержимое одноимённого файла. Не загружайте `.env.local`, `node_modules`, `dist`, `verification`, `test-results`, PDF-инвойсы или резервные копии с личными данными.

1. В репозитории откройте **Settings → Secrets and variables → Actions → Variables → New repository variable**.
2. Создайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` с двумя публичными значениями из Supabase.
3. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
4. Откройте **Actions → Deploy Folio to GitHub Pages → Run workflow** для ветки `main`. Дальше каждый push в `main` обновляет сайт автоматически.
5. Откройте адрес из **Settings → Pages**. Зарегистрируйтесь и войдите. Проверьте на втором устройстве, что видны те же клиенты и инвойсы.

Workflow специально останавливается, если значения Supabase не заполнены: выбранный режим работы — онлайн с общей базой. Исходники могут быть публичными; реальные данные клиентов остаются в Supabase и не входят в репозиторий.

GitHub Pages размещает статическую сборку; вход и данные обслуживает Supabase. Инструкции основаны на [GitHub Pages](https://docs.github.com/en/get-started/start-your-journey/deploying-your-website-automatically) и [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

## Нумерация

У каждого клиента собственный префикс, шаблон номера и независимый счётчик. Настройка находится в **Clients → Add client / Edit details → Invoice numbering**:

| Поле | Пример |
| --- | --- |
| Number pattern | `IVR-{SEQ:2}_{MM}/{YYYY}` |
| Next number | `4` |
| Reset counter | Every month / Every year / Never |
| Результат для октября 2026 | `IVR-04_10/2026` |

Доступны `{SEQ}`, `{SEQ:1}`…`{SEQ:6}`, `{YYYY}`, `{YY}`, `{MM}`, `{DD}`. Префикс — обычный текст перед `{SEQ}`, например `IVR-` для одного клиента и `DEV-` для другого. Дата берётся из **Invoice date**, а не из времени скачивания. После выбора клиента редактор показывает его следующий номер. При выдаче инвойса увеличивается счётчик только этого клиента; повторное скачивание не меняет счётчик. Если номер уже занят, выбирается следующий свободный, чтобы номера документов не повторялись. Изменение шаблона не переименовывает историю.

В **Settings → Default numbering for new clients** остаётся начальный шаблон, который копируется при создании клиента. Изменение этого шаблона не влияет на существующих клиентов. Старые локальные данные и резервные копии автоматически получают отдельные настройки для каждого клиента из прежнего общего шаблона; выданные инвойсы при этом не меняются.

## PDF и история

Инвойсы в этом приложении отражают **полученную полную оплату**. Документ содержит отправителя, клиента и его tax / registration ID, номер и дату инвойса, дату оплаты, строки услуг, quantity, rate, amount, subtotal, tax, total, payment received и balance due = 0. Налог вычисляется от subtotal; дробные количества — до 3 знаков, ставки и налог — до 2. Округление каждой строки до центов, затем округление суммы налога до центов. EUR и USD не складываются в один итог и не конвертируются.

После **Issue invoice** реквизиты и строки фиксируются. Редактирование клиента и настроек не меняет выданные документы. **Use as template** копирует услуги в новый инвойс с новой датой и номером. Архивирование клиента сохраняет все его инвойсы. Ошибочный выданный документ нельзя незаметно редактировать или удалить; при необходимости выпустите новый документ по принятому у вас порядку.

В **Invoice history** есть фильтры **All clients**, **All currencies** и **All years**, а также поиск. Они работают вместе. Фильтр по клиенту включает клиентов с выданными инвойсами, в том числе архивных. Переименование клиента не разрывает его историю.

PDF генерируется в браузере, без отправки содержимого третьему сервису. Шрифты Noto Sans с открытой лицензией включены в `public/fonts`; поддерживаются латиница, кириллица и символы валют. Интерфейс и подписи в PDF на английском. Длинные таблицы продолжаются на следующей странице с повтором заголовка. Это обычный PDF, без электронной подписи и интеграции с государственными системами.

При возвращении на вкладку загружается свежая история. Сохранение проверяет версию всей рабочей области: если другое устройство уже внесло изменения, приложение загружает их и предлагает проверить форму и повторить сохранение. Конкурирующая запись не затирается молча.

## Проверки

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
```

Последняя команда запускает браузерные сценарии и тестовые серверы на портах 4188/4189. Используется установленный Chrome/Edge или Chromium Playwright (`npx.cmd playwright install chromium`). Тесты SQL запускают настоящую схему в изолированном PostgreSQL через PGlite, без подключения к вашей базе. Сценарий входа проверен с подменённым API; реальное подключение проверяется после создания вашего Supabase-проекта.

Стек: React, TypeScript, Vite, Supabase, jsPDF, AutoTable, Lucide. В проекте нет реальных клиентов, личных реквизитов и секретных ключей. Лицензия шрифтов — `public/fonts/OFL.txt`.
